# pyDADA2 porting notes: design, validation and known differences

This document summarises how pyDADA2 was ported from the R package, how it was validated against
R, and every known difference from R. It replaces the working documents used during the port
(the work order, the parity sign-off, the deviation log and an independent review).

pyDADA2 is an **unofficial** port. The algorithms, their C++ implementation and most of the
pipeline logic are the work of the DADA2 authors:

- Based on: <https://github.com/benjjneb/dada2>, ported from commit
  [`b61fe2e`](https://github.com/benjjneb/dada2/tree/b61fe2e90115be08e78a01a16af89fd21402ca42)
  (dada2 1.36.0).
- Paper: Callahan BJ, McMurdie PJ, Rosen MJ, Han AW, Johnson AJA, Holmes SP (2016). DADA2:
  High-resolution sample inference from Illumina amplicon data. *Nature Methods*, 13, 581–583.
  doi:10.1038/nmeth.3869. See the README and `CITATION.cff` for how to cite.

## 1. Design

### Goals

- Provide DADA2's amplicon pipeline (filtering, dereplication, error learning, sample inference,
  read merging, chimera removal, taxonomy) in Python with a scikit-learn-style API.
- **Reuse the upstream C++ core, do not re-implement it.** Only the R/Rcpp glue was replaced.
- **R behaviour (the code, not the docs) is the specification.** Results must match R exactly
  wherever R is deterministic.
- Move performance-relevant R-level logic (and the Bioconductor pieces it relies on) to C++.
- Linux, macOS and Windows; Python ≥ 3.11. 1:1 API compatibility with R is a non-goal.

### Layout

| Path | Contents |
|---|---|
| `cpp/core/` | upstream `src/*.cpp` with Rcpp/RcppParallel removed; public C++ API in `api.h`. Each file's header lists its changes vs upstream. No Python or R headers. |
| `cpp/core/ported/` | new C++ kernels ported from DADA2's R code (table below) |
| `cpp/bindings/module.cpp` | nanobind module `pydada2._core` (private) |
| `src/pydada2/` | the public Python API; `data/` holds the upstream example data and error matrices |
| `tests/parity/` | comparisons against fixtures generated by R dada2 1.36 (`tests/reference/data/`) |
| `tests/unit/`, `tests/e2e/` | unit, property (Hypothesis), determinism and end-to-end tests |
| `benchmarks/` | micro-benchmarks and full-dataset benchmarks against R |

### De-R'ing the C++ core

- Minimal algorithmic diff: only types, IO and glue changed. Numerical changes are listed in §3.
- Rcpp containers → `std::vector`/plain structs and row-major matrix views; R's column-major
  layout is converted at the binding layer. Indices are 0-based, `-1`/NaN mean NA.
- `RcppParallel` → a `parallel_for` on a process-wide persistent thread pool. Results are
  identical for every thread count (tested with 1, 2 and 4 threads).
- `Rcpp::stop` → `std::invalid_argument` (`ValueError`) or `dada2::Error` (`RuntimeError`);
  user interrupts raise `KeyboardInterrupt`. The GIL is released around heavy calls.
- `Rcpp::ppois` → a clean-room Poisson upper tail (Loader's saddle-point dpois plus a series
  below the mode, Boost.Math `gamma_p` above). **No code from R itself (GPL) was copied.**
- `Rcpp::runif` → `std::mt19937_64(random_state)`, drawn in upstream's count and order;
  taxonomy tie-breaking uses a per-sequence generator, so results do not depend on `n_jobs`.
- `std::random_device` tie-breaking in upstream taxonomy → deterministic (upstream R is not
  reproducible there, even with `set.seed`).

### R logic ported to C++ (kernels)

The kernel numbers (K1–K9) are used in code comments.

| # | Kernel (`cpp/core/ported/`) | Ported from (R) | Why |
|---|---|---|---|
| K1 | `fastq_filter` | `fastqFilter`, `fastqPairedFilter`, `trimTails` | R is fast only through ShortRead C code |
| K2 | `derep` | `derepFastq` | idem; reproduces R's chunk-dependent tie order |
| K3 | `merge` | `mergePairs` | per-pair R loop → parallel C++ |
| K4 | `bimera_denovo` | `isBimeraDenovo` | per-sequence R loop → parallel C++ |
| K5 | `collapse` | `collapseNoMismatch`, `isShiftDenovo` | per-sequence R loops |
| K6 | `complexity` | `seqComplexity` | Biostrings k-mer counting |
| K7 | `primers` | `removePrimers` (Biostrings `matchPattern`, incl. indels) | Biostrings C code |
| K8 | `species` | `assignSpecies` (Biostrings `PDict`) | Biostrings C code |
| K9 | quality profile (NumPy, `io.quality_profile`) | `plotQualityProfile` (`ShortRead::qa`) | a bincount is as fast as C++ |

Orchestration, the self-consistency loop, pseudo-pooling, loess error models (`scikit-misc`, with
a NumPy fallback port for degenerate inputs), sequence tables and plotting stay in Python.

## 2. Validation against R

### Method

- `tests/reference/generate_reference.R` runs R dada2 1.36 on the bundled example data and on
  synthetic inputs designed so that every filter, option and method actually changes the result.
  It writes small JSON/NumPy fixtures that are committed; **R is not needed to run the tests.**
- Every R `NAMESPACE` export maps to a Python object (`tests/unit/test_api_coverage.py`).
- Tolerances:

  | Output | Comparison |
  |---|---|
  | sequences, counts, maps, orders, flags, filter counts, merges, chimera calls, species hits | exact |
  | C++ doubles (λ, p-values, birth statistics, scores, mean qualities) | rtol 1e-10 (most are bit-identical) |
  | error rates (loess) | rtol 1e-12 |
  | taxonomy | top hits exact; bootstraps within 3σ of binomial noise, median \|Δ\| ≤ 10; at `min_boot=50` disagreements only where R's bootstrap is within 50 ± 3σ |

- A difference is accepted only if its cause is understood, it is documented in §3 with its
  magnitude, a test pins that magnitude, and it changes no exact-category output.

### Status per R function

| R function | Python | Status |
|---|---|---|
| `filterAndTrim`, `fastqFilter`, `fastqPairedFilter` (single, paired, chunked, `orient.fwd`, `matchIDs`, every filter) | `filter_and_trim`, `fastq_filter`, `fastq_paired_filter` | exact, including R's warnings |
| `removePrimers` (mismatch and indel modes) | `remove_primers` | exact (300 random Biostrings cases) |
| `derepFastq` | `derep_fastq` | exact (mean qualities rtol 1e-12) |

| `nwalign`, `nwhamming`, k-mer distances, `C_eval_pair`, `C_matrixEE`, `C_matchRef` | `align.*`, `_core.*` | exact |
| `ppois` (internal) | `_core.ppois_upper` | rel ≤ 1e-12 (deviation #1) |
| `loessErrfun`, `noqualErrfun`, `makeBinnedQualErrfun`, `PacBioErrfun`, `inflateErr`, `getErrors` | error-model classes, `inflate_err`, `get_errors` | rtol 1e-12 (deviation #4) |
| `learnErrors` | `learn_errors` / `ErrorLearner` | exact transitions, rates rtol 1e-10 |

| `assignTaxonomy` | `TaxonomyClassifier` / `assign_taxonomy` | statistical (deviation #2) |
| `assignSpecies`, `addSpecies` | `SpeciesAssigner` / `assign_species`, `add_species` | exact (deviation #7) |
| end-to-end tutorial pipeline | `tests/e2e/test_pipeline.py` | exact; taxonomy statistical |

### Full datasets

The DADA2 tutorial pipeline was run with both tools on MiSeq SOP (20 samples) and on the full
Stability dataset it comes from (362 samples, 3.65M read pairs), with SILVA 138.2 for taxonomy.

- Every exact output is identical to R: read tracking, uniques, denoised ASVs per sample and
  their order, merged pairs, sequence tables and chimera calls. Error rates agree to rel ≤ 1.4e-14.
- Taxonomy: 229/232 (MiSeq SOP) and 412/420 (Stability) ASVs identical at every level; all
  differences are at a level where R's bootstrap was 41–52, around the `min_boot=50` cutoff.
- Runs are bit-identical across repeats and thread counts.
- pydada2 was 6.0x (1 thread) to 12.1x (8 threads) faster than R on MiSeq SOP and 4.5x on
  Stability. Details: `benchmarks/dataset/REPORT.md`, `REPORT_stability.md`,
  `benchmarks/micro/REPORT.md`.

### Where this has been verified

- **Linux x86_64, Python 3.13:** full suite (1067 tests, 874 of them parity, 97 % coverage) and
  both dataset benchmarks.
- **Memory and thread safety:** AddressSanitizer (`scripts/asan_check.sh`) and ThreadSanitizer
  runs report no errors in the C++ code.
- **macOS (arm64, x86_64), Windows, Linux aarch64, Python 3.11/3.12/3.14 and the built wheels:**
  covered by `.github/workflows/ci.yml`, **not yet run**. Treat these platforms as untested until
  CI is green.

## 3. Known differences from R dada2 1.36

| # | Area | Difference | Cause | Magnitude | Pinned by |
|---|---|---|---|---|---|
| 1 | ppois (abundance p-values) | Clean-room Poisson upper tail (see §1) | no GPL code; plain `gamma_p` underflowed to 0 where R returns a subnormal | ≤ 5.4e-13 vs a 45-digit reference; vs R ≤ 1e-12 for p ≥ 1e-292, ≤ 2.5e-12 below; zero/non-zero pattern identical | `tests/parity/test_core_lowlevel.py::test_ppois_upper*` |
| 2 | taxonomy RNG | bootstrap uniforms from `std::mt19937_64(random_state)`; deterministic tie-breaking | R's RNG is GPL and R's tie-breaking is not reproducible | top hits identical; bootstrap \|Δ\| median 0, max 15; at `min_boot=50`, 8/109 fixture sequences differ at one level, all with an R bootstrap of 42–55 | `tests/parity/test_taxonomy.py::test_deviation_2_magnitude` |
| 3 | `quality_profile` | uses the first `n` reads | R's `qa()` samples `n` reads at random | identical on files with ≤ `n` reads | `test_derep_sequences.py::test_quality_profile_parity` |
| 4 | loess error model | `scikit-misc` loess; when it aborts on R *warnings* (≤ ~8 quality scores), a NumPy port of the same netlib algorithm (`pydada2._loess`) | different builds of netlib dloess | rel ≤ 1e-12 (fallback ≤ 1.2e-12); raises where R fails | `test_error_models.py::test_loess`, `test_loess_fallback.py` |
| 5 | DADA cluster order with `use_quals=False` | R's `ppois` can tie for λ one ulp apart; pydada2 separates them, which can change cluster *creation order* | last-ulp differences of #1 | ASVs, abundances and membership identical; 2–4 rows reordered on synthetic sets via a private path only; never seen with quality-aware λ | quality-aware paths pinned exactly by `test_dada.py` |
| 6 | `learn_errors(randomize=True)` | sample order from `numpy.random.default_rng(random_state)` | different RNG | identical with `randomize=False` (default) | `test_dada.py` |
| 7 | `allow_multiple` species names | joined in code-point order | R's `sort()` uses locale collation | only for names differing in case/punctuation | `test_review_python.py` |
| 8 | `BimeraRemover(method="per-sample").is_bimera_` | sequences absent from a sample are reported False | speed (89 s → 1 s on 30 × 3000) | output table identical | `test_perf_equivalence.py` |

All performance work was verified to change no output (bit-identical on MiSeq SOP at 1 and 8
threads, taxonomy included at the same seed, and on Stability).

**Upstream non-determinism (not a pydada2 deviation).** R breaks taxonomy ties with
`std::random_device`, so `set.seed()` does not make `assignTaxonomy` reproducible (R-vs-R on the
fixtures: bootstrap |Δ| ≤ 2, `minBoot=50` assignments 99/100 identical). pydada2 is
reproducible for a given `random_state`.

**R quirks preserved on purpose.**
- `minQ` only applies when `minQ > truncQ`, and reads are kept when `min(qual) > minQ`.
- `maxN` counts every non-ACGT letter.
- `derep_fastq(n=...)` raises when a chunk contains only zero-length reads.
- `is_shift_denovo(flag_subseqs=True)` has no effect (R never passes it on); pydada2 warns.
- Chunking (`n`) changes output order with `orient_fwd` and the tie order in `derep_fastq`, as
  in R.

**R quirks not reproduced.** The quality encoding is detected once per chunk with ShortRead's
rule; R can re-detect it on a re-oriented subset or force phred+33 after the first `matchIDs`
chunk. Identical for phred+33 data.

**Inputs R rejects but pydada2 accepts.** `seq_complexity` with `window` ≥ sequence length;
reads containing U, X or `*` (counted as non-ACGT); reads shorter than the `orient_fwd` sequence
(treated as not matching).

**Behaviour changes at the C++ level** (no effect on valid inputs; pinned by
`tests/unit/test_behaviour_changes.py`):
- Raise instead of misbehaving: unequal-length aligned strings in `eval_pair`/`pair_consensus`;
  empty primers; sequences ≥ 9999 nt in DADA; samples without sequences; error matrices that are
  not finite or outside [0, 1]; `use_quals=True` without qualities; non-ACGT input to
  `_core.nwalign`; values outside int32 in `table_bimera`/`matrix_ee`; out-of-range k-mer sizes;
  out-of-range transitions in `error.cpp`.
- Upstream bugs fixed: uninitialised `birth_from` for prior-born clusters; a memory leak in
  `C_is_bimera`; stack buffer overflow for taxonomy queries > 9999 nt; uniform-buffer blow-up for
  queries shorter than the k-mer size; `rm_lowcomplex` on reads without any ACGT k-mer;
  single-end `orient_fwd` on reads shorter than the orientation sequence.
- Platform consistency: the SSE k-mer routines are emulated exactly off x86 (R on ARM forces
  `SSE=0` and can differ); `seq_complexity` reproduces R's long-double `sum()` (double-double on
  MSVC).

## 4. Independent review

A full review of the port (C++ diffed against upstream, differential testing against R on
several hundred synthetic inputs, sanitizers, profiling) found, and the follow-up work fixed:

- **ppois underflow** that changed DADA cluster order vs R on 8 of 724 Stability denoising runs
  (fixed, deviation #1), and ppois accuracy at large counts (2.0e-10 → 2.7e-13).
- **loess failures** where R returns an estimate (fixed, deviation #4).
- Sequence-table column order with duplicate sequences, `DADA(priors=...)` with a single string
  or FASTA path, and a set of smaller divergences (fixed and pinned by R fixtures, or documented
  in §3).
- **Thread-unsafe log/interrupt handlers** that could crash under concurrent calls (fixed,
  thread-local; TSan clean) and a series of smaller memory-safety items (fixed).
- Test gaps (filters never exercised by a fixture, no warning comparison) and CI defects (fixed).
- Performance: alignment reuse across self-consistency rounds, concurrent samples, a persistent
  thread pool, a sparse parallel taxonomy model build and faster phiX/species matching, all with
  bit-identical outputs (≈ 3.6–6.6x faster than the reviewed version).

Still open: CI has never run on GitHub (so macOS/Windows parity is unverified) and the PyPI name
(see README, "Status").

## 5. Regenerating fixtures and running R benchmarks

R is only needed to regenerate the parity fixtures or to benchmark against R. Install R with the
Bioconductor dependencies (Rcpp, RcppParallel, Biostrings, ShortRead, jsonlite, ggplot2,
reshape2), then:

```bash
scripts/install_r_dada2.sh                     # dada2 at the ported upstream commit, into $R_LIBS_USER
Rscript tests/reference/generate_reference.R   # ~3.5 min
```

Only `MANIFEST.json` (timestamp) and `taxonomy.json.gz` (upstream's non-reproducible
tie-breaking) should change; anything else means the R side changed. Details:
`tests/reference/README.md`. The dev container installs R and dada2 when built with
`INSTALL_R=true` (see `.devcontainer/devcontainer.json`).
